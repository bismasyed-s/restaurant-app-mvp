Assignment no. 1
Restaurant App MVP (Frontend Only, React Native), Fall 2026
Think about your dining experiences. Have you ever wished you could view a menu, check table availability, and place an order all from your phone to avoid long queues? This Restaurant App is the answer.
- As a Customer: "I'm hungry and in a hurry. I wish I could browse the daily specials and book a table for 7:00 PM so my food is ready when I arrive."
- As a Restaurant Manager: "I have a great menu but struggle with phone-in orders. I'd love to digitize my offerings and manage reservations more efficiently."
Task: Interview yourself as a potential customer. What features would make you download this app? This brainstorming is your "client meeting." The outcome of this interview must feed directly into your SRS in Question 1.

## Deliverables
- SRS Document: A detailed document defining every aspect of the full Restaurant system, scoped to a frontend only implementation.

- MVP Frontend: A working React Native app prototype bringing the core screens to life, built with useState, useEffect, useRef, useContext, useReducer, useMemo, useCallback, and custom hooks.

## Question 3: Login and Signup Screen
Hooks covered: useState
Objective: Use useState to manage form input, validation feedback, and UI mode in a single screen.

### Requirements
- Build a screen that switches between Login and Signup modes using a mode state variable.
- Use controlled inputs. Login needs email and password. Signup additionally needs full name, confirm password, and a role selector (Customer or Manager).
- Keep separate state for the errors object, a show password toggle, and an isSubmitting flag. Errors for a field must clear as soon as the user edits that field.
- Validate on submit: a valid email format, a password of at least eight characters containing at least one digit, and matching password and confirm password.
- Authenticate against a mock users array in src/data/users.js. Simulate network delay with a one second setTimeout, show an ActivityIndicator, and disable the button while submitting.
- On success, navigate a Customer to the Menu screen and a Manager to the Dashboard using React Navigation. On failure, show an Alert with a clear message.
Deliverable: LoginScreen.js, src/data/users.js, and two screenshots (validation errors visible, and successful login).

## Question 4: Menu Browsing Screen
Hooks covered: useState, useEffect
Objective: Load data when a screen mounts, handle loading and error states, and respond to changes in state using useEffect dependency arrays.

### Requirements
- Create src/data/menu.js with at least fifteen items across at least four categories (Starters, Mains, Desserts, Drinks). Each item needs id, name, description, price, category, image, isSpecial, and isAvailable.
- Use a useEffect with an empty dependency array to "fetch" the menu from a Promise that resolves after 1.5 seconds. Maintain menuItems, isLoading, and error states, and display a loading indicator and an error message with a Retry button.
- Show horizontal category chips. Keep the selected category in useState, and use a second useEffect that depends on selectedCategory and menuItems to update the filteredItems state.
- Render items in a FlatList with a keyExtractor, a card layout, and a "Daily Special" badge for items where isSpecial is true. Unavailable items must appear greyed out with the Add button disabled.
- Implement pull to refresh using the refreshing state of FlatList.
- Use a useEffect to update the screen header title with the number of items currently shown.
- Return a cleanup function from the loading effect that clears the timer, so that no state update happens after the screen unmounts.
Deliverable: MenuScreen.js, src/data/menu.js, and a short note (about 100 words) explaining what happens if the dependency array of the filtering effect is left empty.

## Question 5: Search and Scroll Controls
Hooks covered: useRef
Objective: Use refs for values and elements that must persist across renders without causing a re-render.

### Requirements
- Add a search bar to the Menu screen. Use a ref to the TextInput so that tapping the search icon focuses the input, and a clear button empties the text and keeps focus.
- Implement debouncing manually: store the timeout id in a useRef, clear it on every keystroke, apply the search after 400 milliseconds of inactivity, and clear it on unmount.
- Attach a ref to the FlatList and show a floating "Back to top" button (visible only after the user scrolls down 300 pixels, tracked with useState) that calls scrollToOffset.
- Use a useRef counter to count how many times MenuScreen renders, and display it in a small debug label. In comments, explain why changing a ref does not re-render but changing state does.
- Keep the last five search terms in state, show them as tappable suggestions when the input is focused and empty, and use a ref to store the previous query so that duplicate consecutive searches are not added.
- Show a friendly empty state message when no item matches the search.
Deliverable: Updated MenuScreen.js and a screenshot showing the render counter after typing a search term.

## Question 6: Global Auth and Theme
Hooks covered: useContext
Objective: Share state across the whole app without prop drilling, using the Context API.

### Requirements
- Create AuthContext (user, login, logout) and ThemeContext (isDark, toggleTheme) inside src/context, each with a Provider component, and wrap the app in both providers.
- Create two custom consumer hooks, useAuth and useTheme, that throw a descriptive error if they are used outside their provider.
- Refactor Question 3 so that a successful login stores the user in AuthContext instead of local state. Add logout that returns the user to the Login screen and resets the navigation stack.
- Build a Profile screen that shows the logged in user's name, email, and role, and a switch that toggles light and dark mode.
- Define light and dark colour palettes in one theme file. Every screen must read its colours from useTheme, so that the toggle changes the whole app instantly.
- Restrict navigation by role: the Manager Dashboard tab must appear only when user.role is manager.
- In README.md, write five to six lines explaining why context suits this data better than prop drilling, and one drawback of context (all consumers re-render when the value changes).
Deliverable: src/context folder, ProfileScreen.js, and the README note.

## Question 7: Cart Management
Hooks covered: useReducer
Objective: Manage complex, related state transitions with a pure reducer and dispatched actions.

### Requirements
- Create src/reducers/cartReducer.js with state shaped as { items, promoCode, discountPercent }.
- Support at least these actions: ADD_ITEM, REMOVE_ITEM, INCREMENT, DECREMENT (removes the item when the quantity reaches zero), UPDATE_NOTE, CLEAR_CART, APPLY_PROMO, and REMOVE_PROMO. The reducer must be pure and must never mutate the previous state.
- Accept mock promo codes from a local object (for example WELCOME10 for 10 percent and FEAST20 for 20 percent) and reject invalid codes with an error message.
- Create a CartProvider that uses useReducer and exposes state and dispatch through a CartContext, together with a useCart hook.
- Add an Add to Cart button on every menu card, a Cart screen with a quantity stepper, a remove button, and a special instructions field per item (for example "no onions"), and a live item count badge on the cart tab icon.
- Prepare a table of at least six test cases (action, initial state, expected state) and include it in the README. Writing Jest tests for the reducer earns a bonus.
- Write four to five lines in the README comparing useReducer with useState for this cart, and say when useState would have been enough.
Deliverable: cartReducer.js, CartContext.js, CartScreen.js, and the test case table.

## Question 8: Order Summary and Performance
Hooks covered: useMemo, useCallback, React.memo
Objective: Avoid unnecessary calculations and re-renders, and learn when optimisation is actually worthwhile.

### Requirements
- Build an Order Summary screen that calculates subtotal, service charge (5 percent), sales tax (15 percent), promo discount, and grand total. Keep the rates as named constants and compute the totals with useMemo, depending only on the cart items and discount.
- Extract MenuItemCard into its own component wrapped in React.memo. Pass its handlers (add to cart, toggle favourite) using useCallback so that their references stay stable.
- Add a favourite (heart) toggle on each card, with favourite ids kept in one state array. Place a console.log inside MenuItemCard and show, with before and after screenshots, that only the toggled card re-renders once the optimisation is applied.
- Add a sort option on the menu (price low to high, price high to low, name A to Z). Replace the filteredItems state and effect from Question 4 with a single useMemo that applies category filter, search text, and sort order. Explain in comments why derived data should not be stored in state.
- Write a short note (maximum 150 words) on when useMemo and useCallback should not be used.
Deliverable: OrderSummaryScreen.js, MenuItemCard.js, updated MenuScreen.js, two console screenshots, and the note.

## Question 9: Table Reservation
Hooks covered: Custom hooks
Objective: Extract reusable logic from components into custom hooks so that screens contain only UI code.

### Requirements
- Create src/hooks/useForm.js that accepts initial values and a validate function and returns values, errors, handleChange, handleSubmit, reset, and isValid. Refactor the Login and Signup screen from Question 3 to use it.
- Create src/hooks/useDebounce.js (value, delay) and replace the manual ref based debounce of Question 5 with it.
- Create src/hooks/useReservation.js that manages the selected date, time slot, party size, table, and contact details, checks availability against mockTables and mockReservations, and exposes createReservation and cancelReservation. The Reservation screen itself must contain no business logic.
- Offer hourly time slots from 12:00 to 22:00. A slot must appear disabled when no table with enough seats is free at that time.
- Validate that the date is not in the past, the party size is between 1 and 12, the phone number matches the Pakistani mobile format (03XX-XXXXXXX), and the booking is at least one hour ahead.
- Show a confirmation modal summarising the booking before it is saved, and a My Reservations list where each booking can be cancelled after an Alert confirmation.
- Follow the hook rules: names begin with "use", hooks are called only at the top level, and no hook returns JSX.
Deliverable: Three hook files, ReservationScreen.js, and a screenshot of a disabled time slot.

## Question 10: Order Tracking and Manager Dashboard
Hooks covered: useEffect (timers and storage), integration of all hooks
Objective: Combine everything into one working prototype, using effects for timers and local persistence.

### Requirements
- Build the place order flow from the Cart screen. The customer chooses Dine-in (with a table) or Takeaway (with a pickup time) using useState, and placing the order dispatches to an OrdersContext (useReducer) that creates an order with id, items, total, type, status Pending, and a timestamp.
- Build an Order Tracking screen. Use useEffect with setInterval to move the status automatically from Pending to Preparing after 10 seconds, to Ready after 20 seconds, and to Served after 30 seconds (demo timings). Show a step progress indicator and a running elapsed time counter that updates every second. Clear every interval in the cleanup function.
- Build a Manager Dashboard, visible to the Manager role only, with three tabs: Incoming Orders (buttons to change the order status manually), Reservations (accept or decline), and Menu Management (add an item, edit a price, toggle availability). Menu changes must appear on the customer menu immediately through shared state.
- Persist orders, reservations, and menu edits in AsyncStorage using useEffect, and load them when the app starts. Show a loading screen until loading is complete, so that the app never flashes empty data.
- Use bottom tabs with nested stack navigation, safe area handling, and the theme from Question 6 on every screen.
- Test the complete flow: sign up as a customer, browse and search, add items, apply a promo code, reserve a table, place an order, and watch it progress; then log in as a manager and update the same order.
Deliverable: Full source code, and a screen recording (maximum three minutes) of the complete flow, with the link included in the README.
